# dsh++ 低占用与托盘设计

## 目标

避免启动器扫描 DSH 项目依赖树时占用大量 CPU、磁盘和进程资源；后台隐藏时不执行轮询或扫描，并通过系统托盘保持可见提醒。

## 约束

- 默认不自启动、不自动请求 DeepSeek API、不自动扫描系统指令和插件。
- 系统指令扫描仅在用户点击“重新扫描”时执行。
- 扫描跳过 `.git`、`node_modules`、`.pnpm`、构建产物、覆盖率、会话和重解析点。
- 单次扫描限制目录数、匹配文件数、哈希文件大小和时间预算。
- 扫描使用一个低优先级后台线程，并由信号量保证不会并发执行；结果短时缓存。
- 定时刷新只服务于 DSH 管理页状态，默认间隔 10 秒，最短 5 秒。
- 主窗口关闭或最小化进入托盘；托盘菜单提供打开、手动刷新 DSH 状态和退出。
- 退出必须通过托盘“退出”菜单完成，避免后台进程被误认为已退出。
- 单实例互斥，避免多个启动器重复轮询或创建多个托盘图标。

## 验收

- 依赖目录中的 `AGENTS.md` 不会进入扫描结果。
- 取消令牌不会留下后台扫描线程。
- DSH、API、插件原有核心测试继续通过。
- Release 构建和单文件发布成功。
- 启动器启动后主窗口可见，关闭后可从托盘重新打开，托盘菜单可退出。
